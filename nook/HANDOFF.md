## Versions

- **Name:** the app is **Budgie** and its communities are **nests** (still `n/…`). It was called Nook until 0.2.1. Only what people see was renamed: the code, CSS classes, storage keys, the folder `nook/`, the server's `nook` command, service, user and paths, and the live repository's name all still say nook. The starter nests `nookhq` and `asknook` became `budgiehq` and `askbudgie` (the server moves their posts once; old links redirect).
- **Live:** 0.7.0 with the server at https://nook.tailfb59a9.ts.net (the laptop, through Tailscale Funnel), set in `nook/js/config.js`.
  It has accounts, friends, messages, live updates, reports and a Moderation page. Profiles have a picture and a banner (each a photo or a GIF: the GIF moves on profiles and chats, a still copy shows in feeds and when motion is reduced) and a bio of up to 300 characters with line breaks and formatting. Admins can clear a reported profile from the Moderation page or with `nook clear-profile <name>`. Sign-up is open (no code); `nook signups invite` brings codes back.
  0.7.0 made profiles much more customisable, all with Material 3 parts: pronouns (free text up to 24 letters, quick picks, word-list checked), one of 20 pride flags (drawn as SVG in `ui.PRIDE_FLAGS`; no Progress flag, as its licence is non-commercial and Budgie has ads) shown after the name everywhere, up to 6 interests (`ui.INTERESTS`) as chips, a profile colour style (`ui.PROFILE_SCHEMES`: the profile page wears its owner's colour in that Material scheme, when the viewer has "Wear nests’ and profiles’ colours" on) and the shape that floats behind the profile (`data-shapes` on M3 stickers, a small addition to `m3/m3.js`). The server keeps them in `users` (`pronouns`, `pride_flag`, `interests`, `profile_scheme`, `sticker_shape`) and checks each against its own copy of the lists. `nook clear-profile` clears pronouns too.
  0.6.0 lets people pick a font for their name (Edit profile → Name font), shown on their profile, posts, comments, chats and in people lists; Settings → Name fonts turns them off for the reader. The fonts are eight OFL fonts in `nook/fonts/`, cut down to the characters a username can have (a few KB each; licences on `licenses.html`), and `ui.NAME_FONTS` / the server's `NAME_FONTS` list them. To add one: subset it the same way (fontTools, U+0020–007E, woff2), add it to both lists and to the `@font-face` rules in `app.css`.
  Sign-up has an optional robot check, Cloudflare Turnstile (0.5.2; 0.5.1 briefly used Google reCAPTCHA, which the owner swapped for Turnstile because the domain is already on Cloudflare and its keys are simpler to get). It's off until the owner runs `nook captcha <site key> <secret key>` (keys from the Cloudflare dashboard's Turnstile page; steps in `server/README.md`; the command checks the secret with Cloudflare first). The keys live in the database's `meta` table (`turnstile-site`, `turnstile-secret`) and `/api/health` hands the site key to the app, so turning it on or off needs no deploy. `js/account.js` only loads Cloudflare's script when the sign-up form opens; the server checks the answer with Turnstile's siteverify after every other check (so a taken name doesn't use up the answer) and only accepts answers passed on the site's own hostnames.
  0.5.0 added automatic checks on the server (below): pictures for nudity, text with a small AI model, and more word-list rules. Doubtful things are posted and land on the Moderation page as automatic reports.
  Coming from 0.4.0 the laptop needs `sudo nook update`, then `sudo /opt/nook/server/install.sh` once (it raises the service's memory limit from 512 MB to 1.5 GB, which the text model needs, and from then on `nook update` re-runs it with `--update` by itself). The server then downloads the text model by itself (about 300 MB, once); `sudo nook text-check` shows whether it's ready. `sudo nook scan-images` and `sudo nook scan-text` check what was posted before.
- **Ads:** Google AdSense in-feed ads between posts (home, popular, nest feeds only), in `js/ads.js`, off until `ads.client`, `ads.slot` and `ads.layoutKey` are filled in `js/config.js`. The build then writes `ads.txt`. Non-personalised by default; consent comes from Google's own message (AdSense → Privacy & messaging). Auto ads must stay off in AdSense, so there are no banners.
- **Earlier:** 0.1.2 was local-only, behind a client-side code gate. It's gone, and its eight codes don't work on the server.

## Updating the live site

1. Change the code in `nook/` and `m3/` on the source branch. Test it: `node nook/tools/api-test.js` and `node nook/tools/moderation-test.js`.
2. Build into a clone of the live repository: `python3 nook/tools/build-site.py <source repo root> <nook-early-access-website clone>`. Commit and push both.
3. Server changes reach the laptop when the owner runs `sudo nook update` (it pulls, then re-runs `install.sh --update`, which rewrites the service and restarts it).

## How the code is organised

- `nook/index.html` runs two small scripts written into the page (their sha256 fingerprints are in its Content-Security-Policy, with `'strict-dynamic'`, so only they and what they load can run; `python3 nook/tools/csp.py nook/index.html` refreshes them, and the build does it too). The second loads (m3) → `config.js`, `api.js`, `account.js`. Someone not signed in sees the welcome page (`#landing`, plain HTML in `index.html`, so search engines and AdSense can read it; `account.js` wires its buttons and the nest colour demo), and `og.png` is the picture link previews show. `account.js` signs in, fetches `/api/bootstrap` into `window.NOOK_BOOT`, then loads `data, store, ui, moderation, fx, views, app`.
- `store.js` holds the server snapshot and polls `/api/updates?rev&note&msg` every 15 s. Writes are optimistic and undone if the server refuses.
- `server/server.js` is plain Node ≥ 22.5 with `node:sqlite`; nothing is installed from npm. `db.js` holds the schema, with revision stamps for deltas. `cli.js` has the admin commands; `install.sh` sets up the systemd service (memory limit 1536 MB), backups and lid handling.
- `js/moderation.js` holds the word-list rules. The browser and the server both load the same file.
- The server's automatic checks run in worker threads, and their libraries ship ready to run in `server/vendor/` (the build copies it; licences on `licenses.html`):
  - `server/pictures.js`: two NSFWJS image models on TensorFlow.js (WebAssembly), for every picture, banner and GIF frame. Pictures are refused if it can't run (it fails closed). Stricter for profile pictures and banners than for posts.
  - `server/textmodel.js`: Horizon Labs' multilingual-toxicity-small (an mmBERT, 34 languages, Romanian included) on ONNX Runtime's native Linux x86-64 library. The model (268 MB) is too big for git, so the server downloads a pinned version from Hugging Face into `/var/lib/nook/text-model` and checks its sha256. The tokenizer is ours in JS and matches Hugging Face's exactly. It skips itself (and the word lists carry on alone) when it can't run: another platform, under 2.5 GB of RAM, or a service memory limit too low. It uses about 550 MB and 20–40 ms a message. Thresholds per kind of harm are in `LIMITS` (how they were chosen: see Testing); `nook text-check "some text"` shows what it makes of anything.
  - `NOOK_PICTURE_CHECK` and `NOOK_TEXT_CHECK` set to `off` turn them off (emergencies only); `test` scores by markers, for `api-test.js`.
- `promo/ad.html` is a 19-second vertical video ad cut to a 120 BPM beat, in the app's real dark look (open it in a browser to watch it, silently). `node nook/promo/render.js --music sunny` renders it to `nook/promo/budgie-ad.mp4` (1080×1920, 60 fps); `--music sunny,tropical,lofi` makes one video per style, and `--video old.mp4` reuses frames already rendered so only the music changes (seconds instead of minutes). `promo/music.js` writes the music note by note following the `SONG` plan in `ad.html`, plays it with FluidSynth and the MIT-licensed FluidR3 General MIDI instruments (`apt install fluidsynth fluid-soundfont-gm`, or `pacman -S fluidsynth soundfont-fluid`), and masters it to -14 LUFS with ffmpeg. `--stills 1,5,9` saves single frames, `--audio x.wav` just the music. Nothing in `promo/` goes to the live site.

## Testing

`node nook/tools/api-test.js` runs about 110 checks against a temporary server (the picture and text checks in test mode); `node nook/tools/moderation-test.js` checks the word-list rules on 225 English and Romanian sentences. The text model was tuned on about 150 English and Romanian sentences, many built to fool it, and checked on 60 it hadn't seen: with the word lists it stopped or flagged about half the harmful ones there, and flagged 1 in 30 harmless ones for a look (none blocked). It misses indirect bullying ("everyone in class thinks you're a freak"), so people's reports still matter. Browser tests were written with Playwright during development: sign-up, posting, comments, friends, chat, moderation, every button on every page, CSP violations and phone layouts. Re-create them as needed.
